## 3. 方案分解

### 3.0 RL 复训（目标 0）：MJX 初训练 + C++ 复训，95%

**现状**（`rl_stair/configs/rl_stair_config.py` 已核实）：
- T6 = 比赛六级楼梯 + 交接最坏情况：`yaw ±1.0`、`vx -0.5..2.5`、`squat_frac=0.35`、leg_jit DR；
- 初速已有 -0.5..2.5 覆盖 0~2；**起点 0~3 m 位置随机化需核对/补齐**（s10_env 初始 pos 偏移）；
- 当前部署甜点模型 `policy.pt` = r_heading=5 iter-40（wp5→9 集成流验证，非 95%）。

**方案**：
1. **观测/奖励对齐**：确认 obs 55 维含 `cmd_vx` 与 terrain_ctx；奖励含 heading 项（r_heading）——0~2 m/s 初速时策略需学会"起步即加速到爬梯速度"，检查 reward 是否对"初速低→尽快提速"有梯度（如 vx 跟踪项）。
2. **域随机化补齐**：
   - 初速：`c.vx_lo, c.vx_hi = 0.0, 2.0`（重置时 `qvel` 前向分量 + 轮速）；
   - 起点：`init_pos_x/y ∈ 0~3 m`（沿楼梯法线前后，含首级前 0~3 m）；
   - 保持 yaw ±0.3（T6 已配），squat/leg_jit（接管站姿）保留；
   - 域随机化矩阵：PD/质量/摩擦/观测噪声/轮速增益。
3. **MJX 初训练**：`rl_stair/train.py`（1024 env GPU PPO），课程 T0→T6；目标：T6 课程成功率 ≥90%（MJX 内）。
4. **迁移达标**：`sim2sim_exact.py`（比赛精确 box harness）+ `sim2sim.py`（官方 S10_track 真实 mesh）——先做迁移验证（用户规则：C++ 训练前先验证）。
5. **C++ mujoco 环境复训**：官方版本（`pip install "numpy<2.0" mujoco`，保持比赛原环境）——在 C++/mujoco 原环境继续 PPO 微调（或从 MJX 导出的策略 warm-start），直到**批量验收 95% 通过**（如 30/30 或 ≥95/100，按 `迁移达标方案_95percent.md` 口径）。
6. **验收口径**：0~2 m/s 初速 × 0~3 m 起点网格采样，爬完 6 级 + 后腿登顶 +1 m，95% 通过。

**参数变化点**：`rl_stair_config.py`（vx/pos 随机化）、`s10_env.py`（重置初速/起点采样）、`export.py`（导出新策略）、部署 `S10_RL_POLICY` 指向新 pt、`rlstair_ctrl` 若需要支持初速预置。

### 3.1 高程图扫墙严格确认（目标 3.1）——已实现墙通道（lidar 层）

**实现（2026-08-16，`lidar_terrain_v2.py`）**：新增独立**墙通道**，门控 `S10_LIDAR_WALL=1`（默认 0，地形通道完全不动）：
- 近水平射线批：本地俯仰 +25°..+50°（站点俯仰 -40° → 世界仰角 -15°..+10°）、方位 ±100°（`S10_WALL_FOV_H`）；
- 垂直面过滤：`|nz|<S10_WALL_NZ_MAX`(0.4) 且 高度 >`S10_WALL_H_MIN`(0.25) → 写入 `wall_h`/`wall_valid` 栅格（世界系 xy）；
- 地形通道（|nz|≥0.6）保持不变。

**严格确认实测（比赛原图，修正放置法——不动 main_body 地形 body 的 qpos）**：
- 东行段（wp9→10）：走廊墙（x=-4.5 东墙 / x=-11.5 西墙）——贴近时东墙 **165 格**（h 1.17-2.15），从 6.5m 外西墙 **63 格**；
- wp7→8 平台西缘墙：可检出但弱（2 格，h 1.87）；
- 台阶 riser 面也被墙通道抓到（127 格，h 0.54-1.16）——**证明必须用 on/off-path 横向过滤**（`S10_OBST_LAT_MIN`）把 on-path riser 排除出障碍栅格（riser 在 path 上=可爬，墙在 path 两侧=障碍）；
- 地形通道完好：地面格 h≈1.17 正常。

**结论**：默认地形通道确实扫不到墙（NZ_MIN 过滤 + 俯仰几乎全朝下）；加墙通道后**能扫到墙**。视场角已按用户授权调整（`S10_LIDAR_FOV_H` / `S10_WALL_FOV_H`）。

**现状（代码已核实）**：`lidar_terrain_v2.py` 的 group-0 分支用 `S10_LIDAR_NZ_MIN=0.6` 过滤，垂直墙面（|nz|<0.6）被丢弃——**默认高程图看不到墙**；但原始 `mj_multiRay` 射线确实能打到墙（墙在 group 0）。

**核心判别规则（用户 2026-08-16 补充，3.1/3.2 共同地基）**：
- **墙在 path 两侧、特别高** → 墙 = **不可通行域（障碍物）**；
- **stair 在 path 上、阶梯式增长、每级 ≤0.3m** → 楼梯 = **可通行域（爬行目标，不是障碍）**；
- 因此用**两个正交判据**区分：① **凸起高度**（`protrusion = wall_h − 局部地面`，墙 ≫0.3m、台阶每级 ≤0.3m）；② **on/off-path**（墙在两侧、楼梯在 path 上）。实现为：`obstacle = (protrusion>h_min) AND (off-path OR protrusion>h_hard)`，台阶 riser 被高度判据自动排除，高墙保留，path 上超高竖墙硬阻断。

**严格确认步骤**（比赛原图，无头）：
1. 选点：wp1→2 弯道外墙、wp4→5 走廊墙、东行段（wp9→10）墙、wp6→7 楼梯两侧；
2. 在每点放机器人 → `LidarTerrainV2.update()` → 统计：原始命中 vs 过滤后有效格；
3. 输出：墙面方向上 raw hit 数量、|nz| 分布、过滤后该方向是否有格；
4. **on/off-path 标注**：把每个命中按"到 path 中心线的横向距离"分类——墙点应全部 off-path（横向距离 > 阈值），楼梯 riser 应全部 on-path（横向距离 ≈ 0）；
5. 结论：写死"能/不能扫到墙 + 原因（NZ_MIN / 抬升高度 / FOV）" + "on/off-path 分类是否干净"。

**方案（若确认默认看不到）**：双通道改造——
- 地形通道（现状）：保留 `|nz|≥0.6` → h/hmax 高程（爬梯/轮下地形用）；
- **墙/障碍通道（新增）**：同一次 `mj_multiRay` 结果里取 `|nz|<0.6 且 高度>轮径` 的命中 → 写入独立 `wall_occ` 栅格（世界系 xy）；
- **on/off-path 判别**：用 wp 坐标生成的 path 中心线（这是允许的信息），把 wall_occ 格按横向距离分箱——`off-path`（横向 > `S10_OBST_LAT_MIN`）才进"障碍栅格"，`on-path` 的高程上升归"台阶/楼梯"；
- 参数：`S10_LIDAR_NZ_MIN`（地形）、新增 `S10_WALL_NZ_MAX`、`S10_WALL_H_MIN`、`S10_OBST_LAT_MIN`（默认 ~0.6~0.8m，> 轮距半宽+余量）；FOV 已扩到 90°（`S10_LIDAR_FOV_H=90`）。

**验收**：① 三个墙点 `wall_occ` 出现连续占格且全部 off-path；② 楼梯 riser 全部 on-path 且不进入障碍栅格；③ 平地无墙误报为 0。

### 3.4 分段 ref_v 修正（目标 4）

**触发**：某几段航点间巡航跟踪差（如 wp4→5 发卡弯、wp1→2 大转角）——只降该段 ref_v。
**实现**：在 `auto_nav.py` 的 vlim 剖面上按段（wp[i]→wp[i+1]）乘以 `S10_REFV_SEG_{i}` 系数（或一张段表 env `S10_REFV_SEG_LIST="4:0.6,5:0.7"`），**不碰其他段**、不做全局 VMAX 修改。
**验收**：wp4→5 段降速后能过弯不卡死/不东偏，其余段时间与现在一致。

### 3.2 MPPI 避障（目标 3）

**方法**：将高程图 + 墙通道投影到 **xy 平面** → 2D 占据栅格（**只含 off-path 障碍**，on-path 台阶/楼梯不算障碍）→ MPPI 采样轨迹的 cost 中加入障碍惩罚项。

**文献支撑（已列于双数据管线文档）**：
- MPPI 原论文（Williams 2016/2017）：cost 设计、采样轨迹评估——障碍项作为 cost 的一部分；
- DWA（Fox 1997）：速度空间避障、障碍距离评估；
- TEB（Rösmann 2012-2017）：局部轨迹避障；
- 碰撞检测：把占据栅格做距离场（如膨胀 + 最近障碍距离 d_obs），`cost_obs = w_obs * exp(-d_obs/d0)` 或 `w_obs * clip((R_safe - d_obs)/R_safe, 0, 1)`。

**实现**：
1. `_build_elev_tile`（现已有）→ 新增 `build_obst_tile`：把地形/墙通道按高度阈值（高于轮心+余量）投影 xy，**再按到 path 中心线的横向距离过滤（`S10_OBST_LAT_MIN`）：只保留 off-path 障碍**，on-path 高程上升排除（避免把楼梯当障碍），膨胀轮宽；
2. MPPI（`body_mppi.py`）：cost 增加障碍项——对每条采样轨迹，查 `d_obs`（最近障碍距离，可预计算距离场），超阈值即惩罚/置无效；
3. 只对"路径附近 + 前方"的障碍起作用（避免远处误判），用 `S10_OBST_LOOKAHEAD` 控制；
4. 门控：`S10_MPPI_OBST=1` 开（默认 0，先 A/B）。

**参数变化点**：`body_mppi.py`（cost 权重 w_obs、安全半径 R_safe、前瞻）、`cruise_vmc_noros.py`（tile 构建）。

**验收**：在赛道放一个人为障碍（或利用墙/台阶），MPPI 轨迹绕过且不撞；无障碍时轨迹与现在一致（不退化）。

### 3.3 cruise→stair 接管模式1（目标 1.1）

**触发**：过航点（wp 坐标判定，如 wp5 后）+ **lidar 高程图检测到前方楼梯**（连续 riser ≥2、净高 ≥0.4，或按感知确认）。

**接管模式1 状态机**（在 `cruise_vmc_noros.py` 增加 `TAKEOVER1` 模式）：
1. 退出巡航航点跟踪（`fol` 暂停 compute_cmd 对 vx/yaw 的驱动）；
2. **PD 控制**：腿用 stand PD 锁到 stair 站姿（复用现 `S10_PRETRANS` 的 kp60/kd4 逻辑）；轮速由接管控制器给出；
3. **减速**：v 3.5→~2.2（实测 RL 需要 ~2 m/s，0.5/1.5/1.8 会摔）——不是刹到 0；
4. **对准**：用 lidar 高程图判楼梯法线（`detect_risers` 输出的 riser 前沿方向 / 楼梯段法向），调整 yaw 正对（目标 yaw≈法线方向，容差 ±5°）；
5. 对准 + 减速 + 腿到位（leg_err→0）后 → 切 `STAIR`（RL），riser 表用 **lidar 派生**（非已知表）。

**与现状关系**：现有 G3(已知减速)+G5(PRETRANS) 是"已知图版"的接管——本模式用 **lidar 感知版**替换 G3 的对准与减速触发，并把"暂停航点跟踪"显式化。

**参数变化点**：新增 `S10_TAKEOVER1` 门控 + 对准参数（yaw 容差、减速曲线）；删除/禁用 `S10_ELEV_KNOWN_RAMP`（信息合规）。

**验收**：从不同初速/朝向进入 wp5→9 楼梯，接管状态 yaw∈[85°,95°]、vx∈[2.0,2.5]、leg_err<0.15，RL 爬完 6 级。

### 3.4 stair→cruise 接管模式2（目标 2）

**触发**：**后腿高于最后一节台阶高度**（lidar riser 表末级 + 后轮/后腿轮下高程高于末级顶+余量；或 lidar 判定已过末级）。

**接管模式2 状态机**（新增 `TAKEOVER2`）：
1. 退出 stair 模式（RL 停止），**暂停航点跟踪**；
2. **PD 控制**：腿从 RL 高站姿平滑弯回 carvmc 半蹲（复用 `S10_PRETRANS_EXIT` 的 blend 逻辑）；
3. **yaw 对齐**：以 path plan（wp 坐标）方向为目标，PD 调整 yaw 到与 path 一致（容差 ±5°）；
4. 腿到位 + yaw 对齐后 → 切 `CRUISE`，恢复航点跟踪。

**参数变化点**：新增 `S10_TAKEOVER2` 门控 + 触发余量（后腿高过末级 `+0.05~0.1`）、yaw 对齐增益。

**验收**：爬完 6 级后，在平台（wp7→9）以对齐 yaw 稳定交回，无侧翻/滑退；与现有"交回 vx=1.26 稳定"可比或更好。

### 3.5 配置切换与 wp0→10 集成（承接 1/2）

**问题**：wp0→4 巡航必须 v890 env，wp5→9 必须 verified env，互斥且均为进程级 env。
**方案**：接管模式1 天然是切换点——wp5 前用 v890 参数，进入接管模式1 时把 `USE_NAV / VMAX / NAV_HZ / roll / terrain` 等运行时翻转（这些参数需从"启动读一次"改为"每拍可重读或模式内缓存"，逐项核对读取点：`auto_nav.__init__` 的 max_speed、`BodyMPPI.__init__` 的 vx_max 需改为可更新接口）。
**wp4→5 硬边界**：用**已知图触发**（next_idx==5 + ridge_world，y=18.4 台阶）先做 cruise 内部台阶处理（homing+短减速），**不切 RL**（RL 只用于 wp6→7 六级楼梯）——这是信息合规下已知图与感知的边界：台阶处理可先用已知图，楼梯接管必须感知化。

```
 └─ RL 50Hz（STAIR，lidar riser 表注入）
```
