## 0. 文献 / 代码库关键细节（重要）

### 0.1 Chamorro et al., "RL for Blind Stair Climbing with Legged and Wheeled-Legged Robots"（ICRA 2024, arXiv 2402.06143）
- **位置制任务**：episode 6s，spawn 在台阶前 0.3~1m 大致面向台阶，目标在顶台面（含航向）；**主要奖励只在最后 2 秒给**（到目标）——给策略自由探索抬轮/蹬腿组合。
- **非对称 actor-critic**：actor 观测 = 角速度(3,×0.25)、投影重力(3,×1)、目标方向(2,×1)、航向误差(1,×1)、高度指令(1,×1)、**地形布尔 b（爬梯模式开关）(1,×1)**、关节位置(×1)、关节速度(×0.05)、last action(×1)；critic 特权 = 线速度、base 高度、**地形高度网格(187 点, 1.6×1.0m, ×5)**、接触力(×0.01, 5 步滑动平均=0.1s)、摩擦系数。
- **动作**：关节=位置目标(PD)、轮=角速度目标——与 go2w/S10 一致。
- **观测噪声**：角速度±20%、关节位置±1%、关节速度±150%、目标方向/航向 0。
- **课程**：地形列=台阶×2 + 斜坡(0~8.5°) + 离散障碍(≤10cm) + 金字塔坡；台阶列前半=单级渐进高度、后半=连续 5 级。
- **收敛**：单 GPU（A100 16GB）约 5k iterations；实机：Ascento 爬 15cm 台阶（此前不可能）。
- **意义**：布尔模式开关 + 位置制 + 非对称 AC = 本方案直接模板；我们还有 lidar（信息更多）。

### 0.2 go2w_rl_gym（ShengqianChen，Unitree Go2W，已 clone 至 refs/）
- **动作**：16D = 12 腿位置目标 + 4 轮**速度**目标（vel_scale=10）；腿 action_scale=0.25。
- **观测**：73 维（lin_vel×2 + ang_vel×0.25 + commands + dof_err×1 + dof_vel×0.05 + dof_pos + actions），obs_hist=5；privileged=263。
- **PD**：sim 内腿 kp=50/kd=1、轮 kp=40/kd=0.5；**真机部署 g2w.yaml**：腿 kp=50/kd=1、轮 kp=20/kd=0.5，control_dt=0.02（50Hz），wheel_real_indices=[12,13,14,15]，wheel_speed=1，关节序仿真↔真机需映射。
- **默认关节角**：hip=0、thigh=0.67、calf=-1.3、wheel=0。
- **奖励尺度**（legged_gym 标准）：tracking_lin_vel=4.0、tracking_ang_vel=2.0、orientation=-2、base_height=-0.5（目标 0.34m）、torques=-0.0001、dof_vel=-1e-7、action_rate=-0.0002、collision=-0.1、dof_pos_limits=-0.9、hip_action_l2=-0.1、termination=-0.8。
- **课程**：terrain curriculum=True，max_curriculum=1.5，num_rows=10/num_cols=20，terrain_proportions 可配（其 stair_up 配置=1.0）；commands lin_vel_x=[0,2]，heading 未用。
- **部署**：policy 50Hz、`msg_type go`、lin_vel_scale=2.0、ang_vel_scale=0.25、cmd_scale=[2,2,0.25]。

### 0.3 LocoWheeledLegged（Isaac Lab 版 Go2W）
- **动作低通滤波**（部署端 1/2 阶低通，防复杂地形关节抖动）；
- **位姿正则** hip_deviation_l2 / joint_deviation_l2（保持自然站姿）；
- **action_rate clip**（阈值 7.0）与**值函数双重 clip**（PPO 稳定）；
- **last_action 历史长度=1**（防控制信号自激）。

### 0.4 本项目现状（DiAL 分层，作为对照/fallback）

- 力矩合规：腿≤48Nm（模型 ctrlrange 50）、轮≤13.5Nm（模型 ctrlrange 14）。

## 1. 整体方案

### 1.1 定位（已确认）
- **统一一个 RL 策略**同时负责**所有楼梯 + 横脊**（训练用 T5 混合课程）。
- 与 DiAL 并行开发 → **达标后转主力**（DiAL 降 fallback）。
- **文件隔离**：RL 全部在 `rl_stair/`，不修改任何现有源文件（§5）。

### 1.2 部署架构
```text
lidar 高程图 (10Hz) ──> riser/ridge 特征 ──> [策略观测编码] ──┐
AutoNavFollower (20Hz) ──> vx/yaw 指令 ────────────────────┤
IMU/关节状态 (200Hz) ──> proprio ─────────────────────────┤
                                                          v
              RL-terrain 策略 (50Hz, 16D)  <── 技能开关(stair OR ridge)
                                                          |
                腿关节位置目标(12) + 轮速度目标(4)
                                                          v
        PD 力矩 (200Hz) ──> StairStanceGuard (200Hz 安全否决) ──> MuJoCo/真机
```
- 技能区：`stair_confirmed OR ridge_confirmed`（lidar 世界坐标）→ RL；离开粗糙区 → CRUISE；vx 连续不归零。

### 1.3 训练栈：MJX（已确认）
- 理由：与比赛仿真**同一 MuJoCo 物理**（训练成效直接可用）；零安装；sim-to-sim 仅"MJX↔C++ MuJoCo"数值小差异（float32/double），靠 DR 覆盖 + 比赛仿真 play 验证一次。

### 3.5 部署导出（JIT 问题结论，已实测）
- **结论**：`torch.jit.trace(actor, x)` 走 `forward()`（`tanh(MLP(obs))`）**可用、round-trip 误差 0.0**（已用真实 checkpoint `model_latest.pt` 验证）。
- **坑**：`act()` 内 `self.std = ...` 属性原地赋值 → `torch.jit.trace` 报 `Cannot insert a Tensor that requires grad as a constant`；部署**永远用确定性 forward，不采样**，故无影响。
- **工具**：`rl_stair/export.py --ckpt ... --out policy.pt [--onnx ...]`（自动从 state_dict 推断 53/16 维；ONNX 需先 `pip install onnx`）。
- **评估**：`rl_stair/eval.py --ckpt ... --stages T3_stairs6,T5_mixed,T6_handoff`（只读现有 env，无参数/门控改动，输出 succ/fall/timeout/unfinished/progress/risers）。
- **部署端必须逐位复刻 53 维观测顺序**（见 export.py 内 OBS_LAYOUT 注释），是 sim2sim 首要核对项。

### 3.7 训练代码 Bug 修复记录（2026-08-14 17:00）
- **Bug**：`Actor.act()` 与 `Actor.get_dist()` 中 `self.std = torch.exp(self.log_std.detach())` 对 log_std 做了 detach → **exploration std 永远收不到梯度，冻结在 1.0**（实测 340 iter 内 std=1.000 纹丝不动；backward 报 "does not require grad"；去掉 detach 后 log_std 梯度=16.0）。
- **对照**：rsl_rl `ActorCritic` 中 `self.std = nn.Parameter(...)` 直接参与 `Normal(mean, std)` 的 log_prob/entropy，std 可学习。legged_gym/go2w_rl_gym 均基于 rsl_rl，std 随训练收敛（1.0→0.1~0.3 量级）。
- **影响**：std 冻结 → 策略始终大噪声，楼梯/横脊所需的精确落脚与轮速控制学不出来 → 24h 训练大概率失败。
- **修复**：去掉两处 `.detach()`（2 行，非新增参数/门控）。验证：`log_std.grad=16.0`，std 开始自适应。
- **动作**：重启训练（`--resume model_latest.pt`，保留已训 200 iter 权重），PID 107939。

### 3.8 训练代码 Bug 修复记录 2（2026-08-14 17:07，std 膨胀）
- **问题**：修复 std 冻结后，std 反而**线性上行**（iter=100 达 1.203，~+0.004/iter），rew 平坦（-3.2）。
- **诊断**：密集奖励以负项为主（姿态 -2/高度 -0.5/力矩…），总回报系统性为负 → 策略用"增大 std 对冲负优势"（负回报 hedgin），std 持续膨胀 → 最终纯噪声。
- **对照**：go2w_rl_gym `only_positive_rewards = True`（注释 "avoids early termination problems"）；legged_gym 实现 `rew_buf.clip(min=0.)` 且**终止惩罚在 clip 之后加入**。
- **修复**：`S10RLCfg.only_positive_rewards=True`；`_reward` 先 clip 密集奖励≥0，再叠加终止 -0.8（与 legged_gym 顺序一致）。

### 3.12 T0 速度门语义与 1.5 m/s 进梯速度覆盖（2026-08-14 19:50 决策）
- **0.375 m/s 是什么**：T0_flat 晋级门的**平均速度**（course 6m / max_ep_len 800 步×0.02s=16s → 6/16=0.375）。它是"平衡/滚动热身"的**通过条件，不是速度能力目标**。
- **1.5 m/s 进梯速度覆盖**：T1-T6 全部关卡 cmd_vx=0.8-1.8 m/s（go2w 参考：lin_vel_x=[0,2]+速度课程）；T6 交接态初始 vx 采样 ±0.5-2.5 → 巡航以 1.5 m/s 进梯的交接状态在训练范围内。达标后需在 T3/T5 上做 **cmd=1.5 的专项 eval** 验证进梯速度。
- **旧权重探针倒车（19:41，it=800 旧奖励）**：新奖励（progress 4/m + tracking 4）对倒车给近零奖励、对前进给正向梯度 → 不构成剩余收敛时间的阻碍；当前训练 rew 2.3-3.3 上行、std≈1.25 不再膨胀，方向信号健康。
- **决策**：T0 门保持 0.375 不变（它是目前瓶颈，调高只会更慢；速度在 T1+ 阶段训练）；若全局 ~1500 仍 succ=0 再走降难度兜底（goal_y 6→4.5 或 cmd 上调，先论证后改）。


### 3.13 部署链 bug：obs_np default_dof 站姿不一致（2026-08-14 19:55，重要）
