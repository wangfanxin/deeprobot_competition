# Stair 技能方案与数据管线（2026-08-11，HEAD 902b828）

> 本文档总结当前 stair 技能的架构、数据管线、实际控制频率，以及每个子方法的详细说明。
> 配套机制分析见 `stair_机制分析_20260811.md`，文献调研见 `stair_文献调研_跑酷与步态_20260811.md`。

## 一、方案（架构）

按用户指定三层结构实现，加上迭代出的底层控制细节：

```
感知层（已知地图预扫描 + lidar 高程图）
   ↓  riser 表 / stair_world 世界坐标 / 显式轮心 z 参考
规划层（AutoNavFollower 双模式 + 楼梯区 vx 剖面）
   ↓  20Hz 导航指令 + MPPI 轨迹优化
执行层（三套可切换：WBC / CarVMC / FootPlaceVMC）
   ↓  200Hz 16 维力矩（腿 ±48Nm、轮 ±13.5Nm，合规已验证）
Mujoco 仿真
```

### 触发方式

`auto_nav.update_mode`：当前航段 z 升 >0.25 **且** riser 表 y 窗口确认离散台阶 → 切 STAIR；进入后**滞回保持**直到离开楼梯区（y>40.5 或 next 推进），防止台阶底部反复切换导致行为突变侧翻。

### 三套执行层（S10_VMC_MODE 选择）

| 模式 | 楼梯执行器 | 原理 |
|---|---|---|
| `dual` | WBC（VMCController） | 6D wrench + 逐腿地形阻抗 + CPG 抬轮（当前 stair 主力） |
| `car` | CarVMC | 轮驱动 + 差速转向，腿=主动悬架（几何抬放窗） |
| `dual2` / `place` | FootPlaceVMC | 逐轮 IK 放轮（位置控制路线） |

## 二、数据管线

```
启动时已知地图预扫描（对当前 mesh 射线）：
  横脊扫描（dh>0.12）→ ridge_world
  riser 表（dh_s>=0.05 上升沿，限楼梯段末 4m）→ stair_risers（弧长, 高差）
  stair_world（riser 弧长→路径点+切线+射线测台面顶高）→ (位置, 切线, 弧长, 高差, 台面顶)

每控制步（200Hz）计算楼梯输入：
  terr         = stair_wheel_ref(y) - r   （显式轮心 z 参考，v755d 左右轮对称）
  place_z      = 每腿落脚点台面高（CPG 抬升目标）
  step_lift    = CPG 抬放量（sin² 窗，v769 只对高 riser 抬）
  stair_pose   = USC 关键姿态插值因子（前轴到最近棱距离）
  climb_mask   = 每轮是否在 riser 爬升窗（v813）
  pitch_tar    = 楼梯几何抬头/低头
  vx_c         = 楼梯窗内插值到 STAIR_WIN_VX

→ cmd dict → vmc.compute_tau(qpos, qvel, wheel_xyz, wheel_vel, cmd, terr, DT) → 力矩
```

## 三、实际控制频率

| 环节 | 频率 | 说明 |
|---|---|---|
| 控制/仿真环 | **200Hz**（DT=0.005） | 每步重算 terr/place_z/step_lift/stair_pose/climb_mask/pitch + VMC 力矩 |
| 导航 | 20Hz（NAV_HZ=20） | 双模式判定 + 路径/速度剖面 |
| MPPI | 20Hz | N=2048/H=40，单次规划实测 **~12ms**（峰值 47ms），在 50ms 周期内 |
| lidar 高程图 | 10Hz | 局部栅格更新 |
| 本机实时比 | ≈0.53 | 15s 仿真需 28s 墙钟；瓶颈是 mujoco 单步+Python（平均 9.4ms/步），不是 MPPI。真机部署控制环按 200Hz 执行 |

## 四、子方法详细说明

### 1. 楼梯感知与几何建模

- **riser 表预扫描**（v236/v587/v627/v699）：沿平滑路径射线扫描，只取上升沿（`dh_s>=0.05`），限定楼梯段末 4m 内（排除 wp5→6 的下降沿误判和远处台阶）。得到每级 riser 的弧长和高差。
- **stair_world 世界坐标表**（v571）：riser 弧长 → 路径点 + 切线 + 射线落点测台面顶高。供 CPG 几何同步抬放窗——因为 `s_cur` 弧长投影在转弯/卡死时不可靠，用轮轴到 riser 面的**物理距离**触发。
- **stair_wheel_ref 显式轮心 z 参考**（v207/v790/v793）：`w_c(y)=地形+r`，棱前 RAMP_A 平滑抬到台面顶+r。这是文献"轮轨迹显式化"的落地——楼梯区轮心目标不再由 CPG 波形隐含，而是由 riser 表解析生成。v790 增加 **REF_ARC 贴面爬升模式**（轮心在棱前最后 r 米内沿面爬升），v793 改 smoothstep + 段长 0.15m。
- **stair_terrain 阶梯函数**：按 y 返回台面高（区外截断为最近已知级），用于 z_des、踩实判定。

### 2. 步态生成（CPG）

- **CPG 抬放窗**（v568/v571）：按每个 riser 物理位置，前/后轴在 ±swing 窗内 sin² 波形抬放，棱面处达峰。**关键几何**：轴距 0.456m > riser 间距 0.4m，前轮跨 Rk+1 与后轮跨 Rk 只差 0.056m，必须几何同步（自由相位会漂移错位）。
- **riser 高度门控**（v769）：台阶高 ≤ 轮半径（0.081）不抬轮（纯滚动可过），只对高 riser 抬——首级 0.063m 台阶不再提前离地。
- **前轴优先交替**（v736）：后轴抬升乘 `(1-前轴)²` 防同抬（六级楼梯前后轴同时抬→无轮接地卡死）；抬轮幅度上限 `S10_STAIR_LIFT_CAP` 可调。
- **踩实释放**（v755c/v757/v772）：**接触反馈调制相位**（Kimura reflex / ETH 腿效用同源）——前轮过棱且轮高达到台面+r 即连续释放抬升；释放参考用"刚越过的棱"的台面高（不是最近棱，那会导致落地 stair1 后不释放），下一棱 0.20m 内让抬升起量。
- **力限抬轮**（v783-785 `S10_VMC_WBC_LIFT_TMAX`）：抬轮腿姿态 PD 力矩限幅（~30Nm）。抬轮力被限制到低于后轮支撑力，body 不被顶起（这是 pitch 从 -0.3 修复到 0±0.06 的关键）。

### 3. 身体姿态控制（USC 关键姿态）

- **stair_pose 插值**（v752/v789）：前轴到最近棱距离的连续量（棱前 0.05m 起、过棱 0.05m 满），驱动前腿膝伸直 + 后腿收缩（几何前倾，前轮贴台面）。
- **pitch 控制**（v765/v770）：楼梯区几何抬头/低头（`S10_STAIR_PITCH_MODE` 1=抬头、2=低头）；楼梯区姿态力矩上限 25→80Nm（`STAIR_TMAX`），关闭加速俯冲前馈——修复了"抬轮反作用把 body 压低头"。
- **z_des 模式**（v792 `S10_VMC_WBC_Z_MODE`）：0=min 地形（后轮贴地保牵引）/ 1=mean（前后轴平均，body 随前轮升高）/ 2=max。mean 时出现过**四轮全接触瞬间（fn 122N）**，是最接近突破的状态。
- **SQUAT 蹲低**（v817 `S10_STAIR_SQUAT`）：楼梯区动态降低 WBC z_des 偏移，body 蹲低让后轮压实。

### 4. 地形阻抗与轮矩

- **单/双侧垂直阻抗**（v763/v774/v813）：楼梯区默认**单侧**（只下压不吸抬——双侧弹簧在 ramp 目标高于轮位时把前轮"吸"离台面悬空，fn=0 卡死）；v813 增加 **climb_mask 爬升窗**：轮在 riser 爬升窗内用双侧（沿面拉高+面摩擦=贴面爬升），台面上单侧（贴地抓地）。
- **下压余量**（v764 `S10_VMC_WBC_PRESS`）：轮目标下调 6-15mm 压实台面（mujoco 接触间隙 3-8mm 导致轮高到位但 fn=0）。
- **轮矩解锁**（v755b）：楼梯区跳过横脊 μN·r 钳制——台阶 riser 也在 ridge 表里，μN·r 把轮矩压到 1.7Nm 无推力；stair 内保持 13.5Nm（用户"轮力矩越大越好"原则）。
- **抬轮反作用补偿**（v785 `S10_VMC_WBC_Z_LCOMP`）：按抬轮幅度给 body 加下压力，后轮保持贴地推力。
- **keep_lift**（v767 `S10_VMC_WBC_KEEP_LIFT`）：楼梯区抬轮腿保留进 wrench 求解——sl>0.3 屏蔽后 pitch/z 控制对前腿无权威，body 被抬轮反作用顶成低头悬空。

### 5. 导航与速度

- **stair vx 窗**（v292）：楼梯窗内 vx 连续插值到 `STAIR_WIN_VX`（默认 1.8，不归零）——窗内只换腿控制与轮力矩模式，vx 参考保持连续。
- **stair_vx**（链 52）：多级楼梯段（z 升>0.25）限速 `S10_AUTO_STAIR_VX`（默认 2.5）；单级横脊仍用保守 step_vx。
- **vx 低通加快**（v746）：楼梯区 0.04s（巡航 0.25s）——防止楼梯前慢速蠕动导致 CPG 抬轮永远等不到。

### 6. 三种执行层（详细）

**WBC（VMCController，mode=dual，当前主力）**：
- 6D wrench（`A6@12腿力`，pinv 或 QP）分配 body 力/力矩到 4 轮；
- 逐腿地形阻抗 `F = kp_h*(pz_des - pz) - kd_h*vz`（pz_des=terr+r-press），配合单/双侧与 climb_mask；
- 姿态 PD（roll/pitch，楼梯区力矩上限 80Nm）；
- CPG 抬轮目标（q1/q2 偏移）+ 力限（LIFT_TMAX）+ 踩实释放；
- 轮差速 yaw + 轮速 PID（wheel_k=10，wheel_d=0.02 给足突破推力）。

**CarVMC（mode=car）**：
- 轮=驱动+差速转向，腿=每腿独立垂直力（mg/4+roll 分配+pitch 分配+地形阻抗）；
- 楼梯用几何抬放窗（`S10_VMC_STAIR_GAIT`）产生 step_lift。

**FootPlaceVMC（mode=dual2/place）**：
- 逐轮 IK 放轮到 terrain+r（v732 连续抬升轨迹，非二值跳变）；
- 抬升腿 PD 增益降到 1/10（软抬轮），支撑腿承担全部载荷；
- roll 修正对所有腿、pitch 修正只对支撑腿（避免对抗抬放）；
- `S10_FP_REACH` 腿长钳制可调（断崖需 -0.36，stair 默认 -0.16）。

## 五、当前阻塞与结论

- **根因**：力控执行层在**轮离地瞬间失去姿态权威**——前轮抬升 → body 被顶高 → 后轮悬空（fn 弱）→ 无推力 → 无法越过棱边。即使前轮达到正确高度（0.76 > 0.747 目标）且距棱 0.07m，后轮抓地仍不足以推进最后这段。
- 已试 ~47 组实验（WBC/CarVMC/FP、CPG 抬轮/贴面爬升/力限抬轮/反作用补偿/爬升窗/蹲低/动量冲级），全部收敛到同一死锁。
- **结论**：需**位置基全身控制**（IK 放轮 + body 姿态闭环）替换力控执行层，属架构级改动——相关机制（`S10_FP_REACH`、climb_mask、z_mode、LIFT_TMAX 等）已全部落地为可调旋钮。
