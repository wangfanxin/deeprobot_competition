# Stair 技能文献调研：跑酷（Parkour）与步态生成（2026-08-11）

## 一、核心论文与机制

### 1. Balancing Control and Pose Optimization for Wheel-legged Robots (USC, arXiv 2109.09934)
- **不悬空抬轮**：轮子连续驱动 τ=R·F_t，靠"姿态前倾 + 腿伸长"让轮心沿棱边滚动爬升，接触连续。
- **姿态优化**：只解少量关键姿态（前轮在台面/后轮在地面）的 body pitch + CoM + 关节角，两姿态线性插值。
- **关键约束**：CoM 保持在支撑多边形中心、body pitch 最小化、无碰撞。
- 真机 0.36m 台阶成功，多级楼梯无抬腿。

### 2. RL for Blind Stair Climbing with Legged and Wheeled-Legged Robots (Chamorro 2024, arXiv 2402.06143)
- **位置基任务公式（position-based）对爬楼梯至关重要**：给"目标位置"而非"速度命令"，让策略自由探索过障策略。
- **Boolean stair mode**：唯一的楼梯模式开关输入（低层策略可切换平地/楼梯行为）。
- **特权信息**（asymmetric actor-critic）：地形高度图、轮子接触力、摩擦系数只给 critic，部署时不需要外感。
- **课程学习**：单级台阶（高度递增 6 行）→ 连续 5 级楼梯。
- 动作 = 关节位置目标（低层 PD 跟踪）+ 轮子目标角速度。
- Ascento（轮足双足）真机爬 15cm 台阶，此前传统控制不可能。

### 3. Robot Parkour Learning (Zhuang 2023, CoRL, arXiv 2309.05665)
- 单策略端到端视觉 parkour（climb/leap/crawl/tilt/run），输出关节位置目标。
- **两阶段 RL（直配点灵感）**：软动力学约束预训练（障碍可穿透，防探索卡局部极小）→ 硬动力学约束微调。
- 简单奖励：前进 + 机械能守恒 + 存活。
- 障碍高度训练范围 [0.2, 0.45]m，测试到 0.5m（1.53×身高）。

### 4. ANYmal Parkour: Learning Agile Navigation (Hoeller 2024, Science Robotics)
- **分层**：底层 locomotion 技能（walk/jump/climb/crouch）+ 高层策略按地形能力选择技能。
- 高层策略感知每个技能的能力边界，场景自适应。

### 5. Go2-W Long-Distance Real-World Navigation via DRL (2026, arXiv 2606.21387)
- 平地形策略周期性抬脚；**粗糙地形策略四轮保持接触 + 轮子转动**（不抬腿）。
- 真机爬升 24cm 台阶（说明四轮贴地滚动 + 腿姿态配合可爬高台阶）。

### 6. CPG 步态生成（经典 + 现代）
- **Kimura et al. (IJRR 2007)**：CPG + reflex——**reflex 直接调制 CPG 相位**（感官反馈改变振荡周期/相位），reflex 直接生成关节力矩。适应不规则地形。
- **Hopf oscillator + 身体姿态反馈**：body attitude（roll/pitch）作为 sensory feedback 调制 CPG 输出，实现斜坡自适应行走。
- **vestibular feedback 调制 CPG**（2018）：前庭反馈同时实现步态转换 + 粗糙地形适应。
- **Bio-inspired CPG + MLP 多技能**（2025, Scientific Reports）：CPG 与 MLP 端到端联合训练，residual signal 调节振荡 setpoint 生成非节律运动。

### 7. Multi-Legged Robot with Pitch Adjustive Units (2021)
- **pitch 角与障碍高度强相关**：爬垂直障碍需足够 pitch 调整（insufficient pitch → 冲击或失败）。
- 四个可调 pitch 的腿单元独立驱动，保持 body 水平。

## 二、对我们 stair 卡点的经验映射

### 卡点回顾（40+ 组实验确认）
前轮滚上/抬上第一级台面后：body 姿态控制失败（pitch 反复、后轮悬空 3-12mm、fn=0 无推力）、轮子接触/推进不足、卡 y=38.04 死锁。

### 经验映射（按可落地性排序）

| # | 文献机制 | 对我们的启示 | 落地方式 |
|---|---|---|---|
| 1 | **USC 姿态优化：CoM 在支撑多边形中心 + pitch 最小化** | 前轮上台面时 body 应保持"前后轮都在支撑多边形内"，pitch 由几何（台面差/轴距）决定而非自由漂移 | 已实现 stair_pose 雏形（前腿收缩+后腿伸长保 body 水平）；需补 CoM 前移约束（前轮承重） |
| 2 | **CPG + 接触反馈调相位（Kimura）** | 我们的 CPG 相位只由"轴到棱距离"驱动，抬轮不到位也推进相位 → 前轮悬空卡死。应加"轮子接触/轮高到位"反馈门控相位推进（连续量） | 在 CPG 抬放窗加"前轮 wz 达台面+r 才推进相位"（v732 踩实因子被禁用，应启用） |
| 3 | **Go2-W 四轮贴地滚动（24cm 台阶）** | 支持纯滚动路线（NO_LIFT）：四轮保持接触 + 轮子持续驱动 + 腿微调姿态，避免悬空抬轮中断推力 | 继续 NO_LIFT + stair_pose 路线，重点保"四轮接触"（后轮伸长贴地） |
| 4 | **位置基任务（RL Blind Stair）** | 我们导航给 vx 命令，stair 区应给"目标位置"（wp7）驱动，让推进逻辑以"到达"为目标而非恒速 | stair 区 vx 改为"距 wp7 距离的 P 控制 + 下限"（连续，非门控） |
| 5 | **软约束预训练（Robot Parkour）** | 障碍可穿透让探索不卡局部极小——对应我们的仿真：台阶接触容差问题（轮子嵌入 12mm 无 fn）可视为"软约束"，控制应在无 fn 时仍推进（不依赖 fn 反馈） | WBC 支撑腿选择不依赖 fn（用几何/terr），防止"无接触→无推进"死锁 |
| 6 | **pitch 与障碍高度匹配（Pitch Adjustive）** | pitch_tar 应精确 = atan(台阶高/轴距) 且稳定执行，当前 WBC 追 pitch 不稳（±0.13 振荡） | 提高 stair 区 pitch 刚度 + 限制 stair_pose 与 pitch 控制打架（二选一主导） |
| 7 | **分层技能 + Boolean mode（ANYmal parkour / Blind Stair）** | cruise/stair 两个技能由明确标志切换（我们已有 skill 切换）；低层技能内部不应再细分门控 | 保持现状，减少 stair 内部参数种类 |

## 三、综合建议（下一步）

1. **姿态层**（核心）：实现"前轮在台面/后轮在地面"的 USC 关键姿态——body pitch = atan(台面差/轴距) + CoM 前移（前轮承重），用 stair_pose 腿长差 + pitch 刚度共同执行，二选一主导避免打架。
2. **步态层**：CPG 相位推进加"轮高到位"反馈（启用 v732 踩实因子），防止抬轮不到位相位提前。
3. **推进层**：NO_LIFT 纯滚动 + 四轮保持接触（后腿伸长贴地），轮子持续驱动，位置基 vx（距 wp7 距离驱动）。
4. **仿真注意**：地形 main_body 是 freejoint（掉落 13mm），轮子与 STL mesh 接触在微小穿透时无 fn——控制不能依赖 fn 反馈做支撑腿选择，改用几何（terr 台面表 + 轮高）。
