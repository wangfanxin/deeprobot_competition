## 1. 赛程与规则

| 节点 | 时间 | 提交物/事项 |
|---|---|---|
| 初赛 | **8.20 截止** | 技术方案 PDF + 可运行 Demo + 开源协议 + GitHub 链接 |

- **计分**：总成绩 = 完成时间（秒）÷ 模式系数，得分越低排名越靠前；
  30 个定位点须全部完成，未完成不计排名。

  （000_start~032_end），base 进入 wp0 的 0.2m 水平半径计时开始、逐点推进、
  终点停表。必须逐点全部通过、不可跳过。
- **合规**：力矩天然 clip 到 ctrlrange（腿 ±50Nm / 轮 ±14Nm）；
  硬件改装上限 = 1× AGX Orin + 1× 深度相机；仿真主机算力无限制。

## 4. 系统架构

```
mujoco_simulation_ros2.py（仿真节点：S10_track.xml 物理 + viewer + 键盘 + 模式 A/B 接线）
  ├─ 感知：mujoco_lidar（120×48 线 @10Hz，前下 45° 安装）
  │     → points_world → local_map.LocalMap（感知-voxel 世界对齐高程瓦片 60×60@0.1m）
  │     → /local_map 话题 + get_local_map()（rollout 注入，零 retrace）
  │     → elevation_lookup.sample_grid / terrain_cost（纯 jnp 查图）
  ├─ 控制：dial-mpc MBDPI（Nsample 2048 / H14 / Ndiffuse 1，plan_once ≈17Hz）
  │     → s10_mpc/mpc_controller.py（CRUISE/STAIR 双模式 + 前馈重注入）
  │     → s10_mpc/auto_nav.py（模式 A：pursuit + 弯道/坡度/台阶限速 + 状态机）
  └─ 配置：doc/s10_mpc_deploy.yaml（hardware_profile 覆盖）
```

### 4.1 感知（perception/）

- `local_map.py`：纯 numpy 世界对齐高程瓦片——3D 体素栅格（0.05m，
  min-z 去噪）→ 2.5D 瓦片（8×8m 锚定、输出 6×6m=(60,60)）→ 重锚定
  （>2m）+ 重叠带继承 + 最近观测优先 + 空洞填补（inpaint 3 格）。
- `elevation_lookup.py`：纯 jnp 固定形状查图，越界/空洞按"未知不惩罚"。
- **运动学地面注入**（`S10_KIN_GROUND=1` 默认开）：轮子法向支撑 >5N 时把
  "轮心−轮半径"并入点云，修复 riser 阴影导致的轮下地图空洞（真机可移植）。
- **LiDAR 安装**（S10.xml `lidar_site`）：`euler="0 0.79 0"`（前上 ~45°）+
  垂直 ±45°（`S10_LIDAR_PHI_DEG=45`），爬坡 pitch 下地面覆盖最优；
  模型保持官方原样（仅保留 LiDAR site 新增，比赛要求）。

### 4.2 控制（s10_mpc/ + dial-mpc）

- **MBDPI 主控制器**（`mpc_controller.py`）：模式化双配置
  - CRUISE：H14（0.28s 视界），腿 σ=0.3，蹲姿正则 15，leg_ext/lockpush 关；
  - STAIR：H20（0.4s 视界），腿 σ=2.0，放开屈膝（w_crouch=0）、
    leg_ext_w=30（抬腿伸展引导）、lockpush_w=8（顶死才锁前轮）、
    r_clear=60（机身逐级抬升）、attdamp=2.0；切模式零 retrace。
  - 恒定项：`terrain_w_ground=300`（轮-地形贴合，台阶处抬轮核心）、
    `w_clear=60`（机身离地净高）。
- **reward 关键项**（`dial_mpc/envs/s10_env.py`）：r_ground / r_upright /
  r_attdamp / 前瞻抬轮（四轮独立窗口 + 陡升梯度门控）/ MARG stumble /
  台阶区 r_leg 放松 / r_ext / r_lockpush / r_clear / r_path*（折线路径）。
- **MPPI 备选**（`mppi_controller.py`）：早期轻量方案，H30/Ns64 ≈ 4.8Hz，
  已由 MBDPI 取代，保留作 Orin 低算力兜底。
- **auto_nav.py**（模式 A）：折线路径滚动采样 + 高程图 z 轨迹；限速 =
  弯道曲率 × 坡度 × 台阶区；`step_zone`（单级横脊，1.5 m/s）与
  `stair_zone`（连续楼梯，2.5 m/s）分开；脱困（5s 无进展前推 +
  航向锁定）；vyaw 变化率限制（0.8）。

## 9. 夜间自主迭代（2026-08-06 22:00 → 08-07，用户外出 10h）

### 9.1 全局导航层（用户 1.1/1.2：dial-mpc 只做 locomotion）

- **Catmull-Rom 平滑路径**（auto_nav._build_smooth_path）：严格过 33 航点
  （偏差 0.013m）、全长 234m、C1 平滑；替代航点折线直连，解决 pursuit
  切弦绕路。
- **速度剖面**：数值曲率 → `v=min(v_max, √(a_lat/κ))`，R_min clamp 1.0m、
  curve_accel 4.0（71° 弯 2.6m/s 侧翻 → 2.0m/s 安全）；弯道前 5m 前向
  传播减速。
- **单调弧长游标 + 切线投影**（compute_cmd）：CTE 大时最近点弧长在弯道
  滞后 → pursuit 瞄准滞后 → 转弯晚；s_cur 只前进、切线投影推进、上限
  不超前当前航点 2m。**wp3→4 弯道 CTE 1.25m → 0.19m**。
- **横脊预扫描**（sim node._scan_ridge_zones）：mj_ray 沿全局路径扫
  dh>0.08 的离散台阶（112 处），vlim 限速 1.5 + 所在航段 step_zone 标记

模型：点模型 + yaw 一阶惯性(tau=0.06~0.12) + 横向加速度侧翻约束
(|v·ω|>7 m/s² 判失败)。跳过起步转圈段，从 wp0 判点后开始。

结论：yaw_gain 2.5 优于 1.8；vyaw_max 2.0 已够（2.5/3.0 无增益）；
lookahead 1.5 最优（2.0+ 变慢）。

### 10.4 已落地代码改动（auto_nav.py）

### 10.13 MPCC/频率/长视界实验（2026-08-09，目标：0.5s 视界 + 15Hz + 3.5 m/s）

**实验结果（均 mujoco 实测）**：
- MPCC r_progress：W_PROG≥20 全部弯道侧翻（进度激励与弯道稳定性冲突）；
  W_PROG=5~10 稳定但无增益（1.72~2.78）
- 长视界：H≥22 或 dt≥0.025（视界≥0.44s）在 2048 采样下 50~100% 崩溃
  （nr116b H=25: 1/3 成功；nr120 H=25+ref_path: 2/5；nr126b H=22+ref_path: 3/6）
  - 单次可达 3.0~3.2 但均为采样运气，复测崩溃
  - 8192 采样稳定但单次 330ms → 实际频率 2.3~3Hz → 弯道跟不上（实测）
- 转弯蹲低：S10_TURN_CROUCH 0.02~0.8 全部崩溃（蹲低+roll 组合破坏姿态稳定）
- 压弯增强（roll 0.15/0.18）：崩溃

  实际 ~14Hz（2048 采样单次 72ms 空闲）

**结论**：0.5s 视界与 2048 采样/高频控制存在根本矛盾（视界长→采样稀疏→
rollout 质量差→弯道失控；加采样→计算 330ms→控制 3Hz→更失控）。当前
架构稳定边界 = H=20（0.4s 视界）+ 2048 采样 + ~14Hz，即 nr60b（中位
2.76）。3.5 m/s 需要视界内路径感知（MPCC 完整实现）或计算架构升级
（rollout 并行化让 8192 采样跑到 15Hz），超出当前 dial-mpc 配置范围。

### 13.10 cruise 提速总结（2026-08-08，H25/平滑ref/弯道参数）

### 13.9 交接给 stair 会话：ref_path 平滑化经验（2026-08-08 v183，cruise 实测）

**发现**：MPC 的 ref_path 一直从**航点折线**采样（带尖角），而导航 pursuit 走
**平滑全局路径**（圆角+切线因子）——两套线在弯道打架：MPC reward 追锐角折线，
导航层追平滑线 → 弯道走线振荡、速度方差 ±0.5 m/s、偶发卡弯/侧翻。

**改动**（auto_nav.py `ref_path_3d` v183）：改从 `self.path_pts`（平滑全局路径）
按弧长采样，与 pursuit 完全同一条曲线。窗口 = `_s_cur` → 当前航点后 n_wp 个航点
的弧长（+2m 余量），spacing 0.3m。z 仍走高程图+站姿高。

**cruise 实测效果**（H=25、0.5s 视界、2048 采样、wp0→5）：
- 3 跑中位 3.08~3.22 m/s，成功率 3/4；对比折线 ref 的 2.4~3.36 大方差，
  平滑 ref 的弯道段（wp2→4 S 弯）卡弯概率明显下降。
- 翻车点从"弯道内振荡"变为"起步/极端采样"偶发（roll -0.72 在 wp1/wp3）。

**给 stair 的启示**：
1. 楼梯段（wp6→7）若 ref_path 仍用航点折线，riser 尖角会让 MPC 在台阶
   前沿折线瞄准，与 stair 已知地图剖面打架——建议同样从平滑路径采样，
   或至少在台阶区用 stair_wheel_ref 场做 z 参考（已实现），xy 用平滑线。
2. 平滑路径上的弯道（台阶前最后一级的 S 弯）要保证 ref 窗口覆盖到台阶区，
   否则 MPC 看不到台阶入口就进弯。
3. 若 stair 侧已有自己维护的 ref_path 版本，先对齐两处实现（搜索
   `ref_path_3d` 的折线采样段），避免双版本漂移。

### 12.1 现状与结论（v161 实证）

- v161（滚转刹车阈值 0.75→1.0）4/4 失败：r1 爬到 z=0.85 后回滑、卡死超时；

  **随机「四轮齐抬跳」**，单次成功率 ~10–20%（v155 曾到顶 z=1.12），无法保证连续 4 次。

- 根因（v153 实证）：MPC 视界内 cost 表面**没有「前轮先抬→滚→后轮跟→落」的时序信息**。

### 12.3 方案：楼梯段「3D 路径几何剖面」（cruise 同构，无硬门控、无 RL）

**第 0 层：离线几何剖面（已知地图，一次）**

wp6→7 楼梯实测几何：5 级 riser（y=38.4/38.8/39.4/39.8/40.2，顶 z=0.67/0.79/0.92/1.04/1.17），
riser 0.12–0.13m > 轮半径 0.081m（**静态滚不上，必须抬**）；梯面深 ~0.4m；
前后轮轴距 ~0.455m（≈ 一个梯面，具备「前轮上阶、后轮在下一阶」的相位基础）。
沿弧长 s 预计算：

- `base_z_ref(s)`：地形高 + 0.20（站姿），在每级 riser 处按平滑曲线缓升（不跳变）；
- `pitch_ref(s)`：riser 前 0.1m 起仰头（目标 -0.2~-0.4 rad 可调），踏面回平——替代当前
  固定 `stair_pitch_tar`；
- `v_ref(s)`：riser 前 0.15m 减速至 ~1.2，踏面恢复 1.5–2.0（用户「楼梯也要快」，用剖面而非恒定限速）；
- **四轮轮心 z_ref(s)**：平地为地形+0.081；riser 处按「前轮先、后轮延后 Δs≈0.40–0.45m（轴距）」
  生成 min-jerk 抬-落剖面（抬升 0.12–0.15m、窗口 ~0.3m）——即用户此前要求的
  「轮中心 ref_z 与地形+轮半径相关」的显式版。

**第 1 层：在线滚动参考（每 plan 更新，沿用 ref_path 机制）**

从机器人当前弧长投影 s_proj 取前方 0.8–1.2m，滚动生成：base_xy + base_z_ref + pitch_ref +
v_ref + 四轮 z_ref（**世界系**，不受机体倾斜/局部地图遮挡影响——回应「机体倾斜导致高度判定不准」）。

**第 2 层：MPC cost 软跟踪（s10_env._reward）**

- `r_ground` 的 target_z 改用**规划的轮心 z_ref**（感知 lift_need / 接触抬轮降级为兜底安全网）；
- `r_height` / `r_pitch` 跟踪规划的 base_z / pitch 剖面（替换固定 target）；
- `vel_tar` 按 v_ref(s) 滚动；
- 权重沿用 v155 配方（ground=300, clear=120, upright=65, attdamp=5, path=25, head=75,
  path_z=30, wheel_ref=3）+ 新增 pitch 剖面项 ~10–20；探索 σ 不变；**允许偏离**（软约束）。

### 12.4 与 v160 的区别（为何这次可能不同）

v160 是「当前时刻静态公式」：lift = max(h_ahead − h_terrain)，后轮 0.5× 前轮，
无时序、无轨迹形状 → 4/4 失败。本方案是**弧长调度的四轮轨迹剖面**：前轮提前抬、
后轮按轴距延后、抬-落用平滑曲线、随 s_proj 滚动——MPC 每个 plan 都能看到完整序列，
而不仅是「当前该抬多高」。

### 12.5 实施步骤与验证

1. `auto_nav.py`：新增 `stair_profile` 预计算 + `ref_pose()` / `ref_wheel_z()` 在线滚动；
2. `s10_env.py`：`target_z` 换规划参考 + pitch 剖面项（其余机制保留为兜底）；
3. sim 节点：每 plan 注入 profile（纯 numpy，<0.1ms，不影响 15Hz）；
4. 验证：wp6→wp7 单轮成功率 → 连续 4 次 → 全航点。

### 12.6 风险与备选

- 风险 A：参考过「硬」→ MPC 追参考反而滚不过。缓解：权重软、允许偏离、接触兜底。
- 风险 B：速度波动导致参考与机体错位。缓解：每 plan 从 s_proj 重生成，参考窗口 > 一个梯面。
- 备选 1：四轮独立参考仍不稳 → 降级「前对 / 后对」两相参考（FL/FR 同轨、HL/HR 同轨），序列复杂度减半。
- 备选 2：加**几何调度的轮速剖面**软参考（riser 前轮速→0，即用户 B 的锁轮软约束按几何调度触发，
  而非接触触发）——若 r_wheel_ref 不足时启用。

   即 12.3 三层一起做（这是「规划路径」的延伸，不是硬步态、不是 RL）。

## 14. 跑酷四足论文研读与 P1/P2/P3 评估（2026-08-08）

### 14.1 论文研读汇总

**总论**：能爬箱子/跑酷/竞速的四足（Go2/A1/ANYmal/Lite3/Go2-W）走三条路线——
RL 端到端（Extreme Parkour、PIE、Robot Parkour Learning、VIP-Loco）、NMPC+TO
（Perceptive NMPC、TAMOLS、Bjelonic Whole-Body MPC）、混合分层（motion library +
online MPC、ABS 双策略、Go2-W 竞速）。对 DIAL-MPC 可迁移的不是网络，而是四件事：
**cost 表面、参考先验、感知表示、分层仲裁**。

**cost/奖励表面（P0 类）**：

| 论文 | 原 reward | 可迁移点 |
|---|---|---|
| Extreme Parkour（ICRA 2024, arXiv 2309.14341） | r_tracking=min(⟨v_world,d̂_wp⟩,v_cmd)；r_clearance=-Σ c_i·M[p_i]（落点距边缘<5cm 罚）；r_stylized 内积+开关 W | 世界系航点速度奖励+cap（防冲过头/绕远）；边缘罚（防 v186 平台掉楼）；样式开关 = CRUISE/STAIR 权重切换 |
| VIP-Loco（CASE 2026, arXiv 2603.14345） | exp 速度跟踪、stuck -1、feet air time +0.5、edge -1、wheel penalty、碰撞 -1 | 卡住/悬空/边缘/滑转罚；感知 10Hz/控制 50Hz 双频与 LiDAR 10Hz+MPC 15Hz 同构 |
| PIE（RA-L 2024, arXiv 2408.13740） | exp 跟踪、orientation -|g|²、vz²、joint power、碰撞计数 | joint power 比 action rate 更物理（锁轮推身） |
| go2w_rl_gym（本地 refs/go2w_rl_gym） | tracking 4/2、orientation -2、base_height -0.5@0.34m、stumble、collision、stand_still、hip_action_l2 | base_height 是软目标非固定蹲姿；命令空间 [vx,vy,vyaw,height] |

**参考先验（P1 类）**：
- **Offline motion libraries + online MPC**（IJRR 2022，Grandia/Jenelten/Hutter）：离线 TO
  技能库+在线 MPC 跟踪，明示是"长时域技能 vs 短视 MPC"的桥梁。我们的 v168/v176
  `stair_action_bias`（场驱动时变四轮偏置 + Y-blend 0.30）就是 1 个原语的闭环化实现，
  且是唯一实证过 riser2 的配方。
- **Qi et al. IROS 2021 感知爬楼**（Aliengo 稳定爬 16cm 阶）：楼梯几何→简单优化生成
  爬升速度+落足参考→底层只跟踪（不学习）——与 §12.3 的 3D 几何剖面同构。
- **TAMOLS**（T-RO 2022, arXiv 2206.14049）：base pose+foothold 联合 TO over 高程图；
  "参考是吸引子不是硬约束"。
- **Hwangbo MCTS / Raibert 脚步启发**：最小 swing 0.2s（防弹跳滞回）；"离障碍距离 =
  swing 时长×v"。

**感知表示（P2 类）**：
- go2w 官方高度测量栅格 17×11=187 点，覆盖 **1.6×1.0m（x 从 -0.8 到 +0.8，含身后）**；
- Extreme Parkour scandots（稀疏扫描点直进策略，不建完整栅格）；
- ABS ray distances（log 射线距离，避障/风险判定低维特征）；
- DreamWaQ（arXiv 2301.10602）：本体感隐式估计地形高度（LiDAR 掉帧兜底）。

**高速转向（AVEC 2026，Go2-W 竞速，arXiv 2606.26313）**：
- 动态自行车+主动 roll 模型；skid-steering 差分轮速产生 yaw，**膝关节左右不对称产生
  anti-roll 力矩**；
- LTR = 2h/w·(ay/g·cosθ+sinθ)（±1=轮离地）；最优压弯角 **θ\* = -atan(v·ψ̇/g)**；
- 架构：离线 time-optimal raceline [x,y,ψ,v](s) → 在线 MPC 跟踪 → 低层策略维持对称站姿；
- 实测：LTR -44%、圈速 -8.7%、峰值侧向加速度 +21.3% 到 1.98 m/s²；
- 落地：ref_path 升级带 ψ_d(s)；cost 加 w_roll·(roll−θ\*)²；弯道给左右膝/胯不对称采样
  偏置（BANK_ROLL）；"胯外翻"是辅助，主因是 roll 对齐 θ\*。

**论文清单**：2309.14341（Extreme Parkour）、2603.14345（VIP-Loco）、2408.13740（PIE）、
2309.09292（Robot Parkour Learning）、2401.17583（ABS）、2409.13678（SoloParkour）、
2206.14049（TAMOLS）、2208.08373（Perceptive NMPC）、2606.26313（Go2-W 竞速）、

### 14.2 P1/P2/P3 深入评估（基于 v176/v186 实证证据）

#### 14.2.0 核心机理：棱线平衡点卡死

- v176 卡死数据：riser3（y=38.775，顶面 z=0.79）卡约 12s，轮心 z 在 0.86–0.88 抖动；
  **0.79 + 轮半径 0.081 = 0.871**，即轮底正好压在台阶棱线上（棱线平衡点）；此时
  `stair_wheel_ref` 目标 = 0.79+0.081+0.05(margin) = 0.921，**只差 4–6cm 翻不过去**；
  12s 后侥幸通过，随后 3、4 级快速过，第 5 级重复死锁；3/3 零翻车，最高 y=39.0、
  基座 z≈1.0。
- v186：超时放宽到 120s → 爬到 y=38.7 后**西漂 7m 掉楼** → 长爬升必须防西漂（HEAD_LOCK）。
- 结论：卡死不是"整体抬得不够高"（基座已到 z≈1.0），而是**"棱线平衡点差 4–6cm 抬升 +
  空中前滚"**两个具体缺口。

#### 14.2.1 P1 参考先验

**现状（代码已核）**：stair_wheel_ref / stair_base_z_ref / stair_pitch_ref / stair_v_ref
四剖面 + v168 时变四轮 bias（`(H,12)`，欠抬量驱动，Y-blend 0.30 收敛，v176 方向：
hipy 0.20/knee -0.50 前、-0.10/+0.45 后）。已是"场驱动闭环运动原语"，比离线库更强。

**三个缺口**：
1. **bias 无轮速通道**：动作空间 16 维（`vel_ref = -a[12:] * vel_scale`），bias 只有 12 维
   关节通道 → 轮子空中"前滚"无采样先验 → 轮速正反震荡的根因。改：bias 扩 `(H,16)`，
   抬升窗口内 `a[12:] += k·vx`。
2. **S10_STAIR_LIFT_MARGIN=0.05 正好等于棱线平衡点差量（4–6cm）**：提 0.10~0.12 可能
   直接解死锁（纯 env var，零代码）。
3. **无 swing-hold**：r_airpen（前轮悬空>0.2s 罚）+ one-way ground 会把轮拉回 → cost 自己
   压制跨棱所需的 0.3–0.5s 悬空。改：轮心过棱后 0.25s 软 hold 窗口（Hwangbo 最小 swing）。

**子项评估**：

| P1 子项 | 价值 | 成本/风险 | 结论 |
|---|---|---|---|
| LIFT_MARGIN 0.05→0.10~0.12 | 高（直击棱线平衡点） | 零，env var sweep | 最先做 |
| 轮速前滚通道（a[12:] bias） | 高（治轮速震荡+棱线死锁） | 低，numpy 侧小改 | 与 hold 一起做 |
| swing-hold 0.25s 软窗口 | 中高 | 低 | 与轮速通道一起做 |
| 前/后腿分相触发 | 中高（治"前轮上、后轮卡第二级"） | 中 | 次之 |
| 原语库化 FRONT/REAR_LIFT | 中（现状已是其超集） | 中 | 不单独做 |
| BANK_ROLL 原语 | 低（属高速转向，roll 项未开） | 中 | 后置 |
| terrain-relative base height | 低（基座已到 z≈1.0，BASE_LAG 已等价） | — | 不做 |

#### 14.2.2 P2 感知

**现状（代码已核）**：LocalMap 8m 瓦片/6m 有效输出（60×60@0.1m），世界对齐机器人居中，
前后各 ±3m（**覆盖已远超 go2w 的 1.6×1.0**）；`S10_KIN_GROUND=1` 轮下接触点注入点云
（=DreamWaQ 兜底已有，chain 41 修 riser 阴影恒空洞）；台阶区 rollout ground cost 用
**已知解析 wheel_ref 网格**（stair_wheel_ref_grid 注入瓦片 feature）。

**缺口**：
1. **棱线在 LiDAR 瓦片模糊**：体素化取 min-z，0.1m 格把 riser 立面抹 1–2 格（0.1–0.2m）；
   且台阶区**限速（前向 0.5~2m 采坡度）和 leg assist 仍读 LiDAR 瓦片**，棱线抹平会
   提前/滞后触发 → 台阶区内这些消费者改读已知 wheel_ref 网格（现成 numpy 场）。
2. **点云浮空（pitch 变化）**：worker 世界变换用快照位姿，原理正确；浮空感来自 min-z
   体素化把竖直立面压成悬空面/可视化残影。可加轮下接触点**垂直偏移注册校正**。
3. DreamWaQ 完整实现（本体感地形估计）：低价值，跳过（接触注入已有）。

#### 14.2.3 P3 分层恢复

**现状（代码已核）**：CRUISE/STAIR 双模式+滞回已有（v31 教训：权重突变→侧翻）；
stall→固定前推恢复已有（`_stall_t>5s`：vx>0.5 且 v_now<0.3 → 前推 2.5/1.2 m/s +
heading 锁，最多 5s）；HEAD_LOCK（`_stair_heading_tau_bias`，tau 层软修正，默认关）
v189 已配好未干净验证。

**问题**：
1. jitter 死锁时瞬时速度可能 >0.3 → stall 检测不触发（12s 卡死即证据）；
2. 恢复动作是硬前推（最硬门控），台阶区 2.5 m/s 实测 roll -0.4 侧倾；
3. v186 西漂 7m 掉楼 → HEAD_LOCK 应开。

**建议（ABS 式但软）**：风险指标改**3s 位移窗口<0.2m**（治 jitter 死锁）；触发后不是
硬覆盖 set_cmd，而是**同 MPC 内换权重集**（v 目标降、LIFT_MARGIN 升、w_push 升、yaw 锁），
机制复用 CRUISE↔STAIR 权重切换；退出带滞回防振荡。
