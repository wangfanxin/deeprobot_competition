# RL-Stair 奖励增强方案：4 项爬梯专项 shaping（S10 适配版）

> 状态：**待用户批准后落地**（符合"不准乱加参数/门控，先论证后加入"约定）。
> 依据：Isaac Lab rough cfg、legged_gym、爬梯调参检查表（lsqyrobot 2026）、Chamorro ICRA 2024 (2402.06143)、Wheely ICRA 2024。
> 原则：**不原样抄**——S10 是轮足狗（无"脚"、有轮），逐项按 S10 几何/动力学适配。
> 约束：**只改 reward/termination，不动 55 维观测 → 导出/部署链零改动**（obs_np.py、export.py、sim2sim.py 均无需改）。
> 时机：**不热改当前 T5 训练**（避免破坏已收敛课程状态），见 §2 落地窗口。

## 0. 动机（为什么 T1-3 成功率低 + 为什么加这 4 项）

当前奖励（s10_env.py `_reward`，2026-08-15 实测）= 推进 progress(4.0) + riser 计数(3.0) + 目标(10) + 姿态(-2.0) + 地形相对高度(-0.5) + 力矩/动作率/限位/髋部 + 速度跟踪 + 航向。
**缺少爬梯专项 shaping**：无抬轮清障引导、无蹭台阶惩罚、无机身碰台阶终止。

对照文献/开源检查表，爬梯任务比平地多出的核心项是：抬脚(轮)清障、防撞立面、防蹭腿/机身、机身碰撞终止。缺这些时，政策只能靠 progress 奖励"盲搜"抬轮轨迹 → 出现检查表列出的典型失败：前轮撞立面、抬不够卡边、蹭腹/蹭腿、只冲不慢。这就是 T1-3（尤其 T1d 12.5cm 单级，仅 2.2cm 抬升裕量）反复回退的直接诱因之一。

本方案 4 项全部有文献/开源原文背书，且每项都给了 S10 适配论证。

## 1. 各项方案

### 1.1 base_contact termination：机身碰台阶即终止 【最高优先】

- **文献**：Isaac Lab rough cfg `base_contact -> done`；爬梯检查表："机身碰楼梯通常应直接 reset，否则 policy 会学到用肚子蹭上去"。
- **S10 适配**：S10 机身 = base_link。纯几何判定，不需要接触力：
  `body_contact = base_z < terrain_under_base + 0.04`
  - `terrain_under_base`：已有函数（r_height 同款，按 riser_y/riser_top 查表）。
  - 裕量论证：stand_z=0.359、轮 R=0.081、轴距 0.456，机身站立时离地约 0.28m >> 0.04m → 正常站/爬不会误杀；只有真正"趴/蹭"才触发。
- **实现**：`term |= body_contact`（并入现有 term，复用 r_termination=-0.8，不新增权重）。
- **可行性**：✅ 纯 qpos + terrain 表，零接触力依赖。
- **预期**：消灭"腹部蹭台阶/趴着上去"（T5 第二横脊后失稳的候选根因之一）。
- **风险**：低。若 0.04 太严可放宽至 0.06（仍有 ~0.22m 安全裕量）。

### 1.2 undesired_contacts → 膝/腿蹭台阶惩罚（几何代理） 【高优先】

- **文献**：Isaac Lab rough cfg `undesired_contacts = RewTerm(weight=-1.0, body_names=".*THIGH", threshold=1.0)`；检查表："thigh/calf 惩罚、foot 允许"。
- **S10 适配**：轮足没有"foot swing"，蹭刮体是**膝/腿**（fl/fr/hl/hr_knee）。用几何代理：
  `scrape = Σ_knee clip(th_knee - knee_z + 0.02, 0, None)`，`r += r_scrape * scrape`
  - `th_knee` = knee(x,y) 处地形高（查表）；`knee_z` = body xpos 的 z（MJX Data.xpos 直接给，无需 FK）。
  - 0.02m = 贴地容差（允许正常过坡，惩罚真正蹭刮）。
- **权重建议**：`r_scrape = -1.0`（Isaac Lab 同量级；先 -0.5 后视曲线加）。
- **可行性**：✅ xpos + terrain 表，vmap 友好。
- **预期**：禁止"膝当滑板/腿蹭台阶"。
- **风险**：中低——正常行走膝离地 >0.1m，不会误伤；仅当轮足姿态异常（膝触地）才触发。

### 1.3 wheel_edge_clearance：前轮跨棱清障 shaping（替代 feet_clearance） 【中优先】

- **文献**：检查表 feet_clearance **目标高度型**："`err = foot_z - target_clearance; reward = exp(-err²/σ)`，target = 地形高度 + 安全余量（3-8cm）"，并明确**"不是越高越好"**（防夸张高抬腿）。legged_gym 用 feet_air_time 门控。
- **S10 适配**：轮足无脚，但**前轮必须抬过 riser 棱线**——12.5cm riser 对轮 R=8.1cm 必须抬轮（T1d 仅 2.2cm 裕量失败的根因）。形状化：
  - 当某轮 y 进入下一级 riser 窗口（`|wheel_y - riser_y| < 0.15`）时：
    `r_wheel_clear += r_wheel_clear_w * exp(-((wheel_z - riser_top)/0.05)²)`
  - 即轮心越接近"棱线顶上方"越好，高斯温和塑形；跨过后由 r_riser(+3) 给稀疏大分。
  - 与 r_riser 分工：r_riser=跨过后的奖励；本项=跨棱瞬间的稠密引导，两者不冲突。
- **权重建议**：`r_wheel_clear_w = 0.5`（先小，避免与推进奖励对抗）。
- **可行性**：✅ xpos + riser 表。
- **风险**：中——可能与"冲上去"策略竞争；**这是唯一需要落地后观察微调的项**（若平均速度下降>5% 则降权或缩窗口）。

### 1.4 wheel_stumble：轮卡立面惩罚（替代 feet_stumble） 【中优先】

- **文献**：检查表 feet_stumble（legged_gym 思路）：足端水平接触力 >> 垂直 → 撞立面惩罚。
- **S10 适配**：轮子始终滚动接触，**水平力大是正常的**（驱动/制动），"水平力比"不适用（这是不能原样抄的关键点）。改为**几何"卡面"惩罚**：
  - 当轮 y 越过 riser 底部 y（`wheel_y > riser_y`）但轮心仍低于棱线顶（`wheel_z < riser_top - 0.02`）时（轮被立面顶住/正在硬顶）：
    `r_wheel_stumble += r_wheel_stumble_w * clip(riser_top - wheel_z, 0, None)`
  - **窗口必须窄**：只在"轮 y 进入 riser 面且轮 z 明显低于顶"时触发，避免惩罚 S10 正常的"轮贴立面滚动爬升"（这是 S10 爬梯的核心机理，误伤代价高）。
- **权重建议**：`r_wheel_stumble_w = -1.0`。
- **可行性**：✅ 几何。**落地前先用当前 policy 的离线 rollout 验证窗口命中率**（应只命中"卡面"帧，不命中"贴面爬升"帧）。
- **风险**：中——最容易误伤的一项，必须做离线窗口验证后再上。

### 1.5（备用）contact-force 精确版
- MJX 3.11 实测（本机验证）：`data.efc_force`(shape 2220) + `contact.efc_address/geom1/geom2` 可导出每接触力 → 可做 Isaac Lab 式 undesired_contacts **精确版**（按 geom 分组求和，权重 -1.0）。
- **先上几何代理（1.2/1.4）**；若代理误伤/不灵敏，再升级为接触力精确版（vmap 分组求和复杂度更高，故不首推）。

### 5.1 impratio 探针（新证据，修正 §3.36 部分认知）
同模型（胶囊轮训练 XML）同参数（solver Newton/iter 100/ls 50/tol 1e-8/cone pyramidal/impratio 1），平地轮速跟踪实验（vel_cmd=12 rad/s，PD 同训练）：
- C++ mujoco：轮速 **11.90** rad/s
- MJX impratio=1：**12.16** rad/s（与 C++ 差 **2.2%**）
- MJX impratio=100：**13.74** rad/s（更大）
**结论**：MJX 3.11 已支持 `mx.opt.impratio`（默认 1.0，与 C++ 一致）；**平地轮驱 MJX≈C++**，§3.36 的 2.7× 只出现在**接触密集场景**（台阶棱/网格），几何差（圆柱↔胶囊）才是迁移主因；impratio 调高反而增大差距，**无需改动**。
